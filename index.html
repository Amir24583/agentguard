What it checks

  • Leaked secrets. API keys and tokens sitting in agent and MCP config files.
  • Open servers. MCP servers reachable from the network with no login.
  • Poisoned tools. Tool descriptions that carry hidden instructions for the model.
  • Too much power. Tools with shell or whole-disk access the agent doesn't need.
  • Unpinned packages. Servers that install whatever version is newest at run time.

Checks are fixed rules, so the same config always gets the same result, and your code is never sent to an AI model.

How you'll use it

# .github/workflows/agentguard.yml (planned)
on: [pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: agentguard/scan@v1
        with:
          config: mcp.json

A failed check blocks the pull request and comments with the fix. Prefer your own pipeline? Send the same file to the API and get the report back as JSON.
